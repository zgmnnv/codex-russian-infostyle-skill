# Критерии проверки ответа

Сравнивай ответ с запросом, исходным текстом, известными условиями и выбранным режимом. Учитывай весь ответ: придуманное обещание в пояснении тоже может ввести читателя в заблуждение. Допустимы разные формулировки, если они проходят четыре проверки.

| Ключ | Когда ставить PASS | Пример причины FAIL |
|---|---|---|
| facts | Все утверждения опираются на исходник или переданный контекст. Сохранены границы выборки, точность, единицы, даты и область действия цены. | Из сбоя сохранения вывели лимит файла. Из поддержки экспорта вывели скачивание Excel. |
| meaning | Сохранены предмет, действующее лицо, обязательность, стадия, доступное действие и существенные условия. Договорные формулировки сохранены. | Объявленную возможность превратили в поручение. Попросили проверить отсутствующий адрес. |
| reader | Адресат может понять сообщение или выполнить задачу для своего состояния и роли. Названия элементов совпадают с интерфейсом, причинность и последовательность различимы. | Пользователю с правом просмотра предложили создать афишу. Для сотрудника пропал нужный раздел инструкции. |
| delivery | Ответ соблюдает запрошенные жанр, формат и объём вмешательства. Голос автора, уместный повтор и тон сохранены. | На просьбу дать только кнопку добавлен разбор. В интервью точную реплику заменили канцеляризмом. |

Для кнопки без чисел все четыре проверки применимы. При недостатке данных допустим точный вариант по имеющимся фактам или короткий вопрос, когда от ответа зависит правка. Для режима проверки без редактуры оцени предложенное замечание. Для уже ясного текста допустимо сохранить исходник. В тесте с юридическим текстом проверь сам результат: одного упоминания юриста недостаточно, если условия уже переписаны.

По каждому критерию поставь PASS или FAIL. Запиши краткое обоснование со ссылкой на факт из задания и на решение в ответе. Итог кейса — PASS, только если пройдены все четыре критерия. Неразобранный кейс получает REVIEW.
